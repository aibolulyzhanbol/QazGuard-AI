# QazGuard-AI
# QazGuard AI: LLM-ге кететін сұраныстарды қорғау шлюзі

ICT1103 · QAIRU · 2026–2027 Endterm, топтық жоба.

QazGuard AI қызметкер мен сыртқы ЖИ-дің (мысалы, ChatGPT) арасында тұрады: құпия деректерді токенмен алмастырады, шабуыл сұранысын бұғаттайды, ал ЖИ жауабындағы токендерді бастапқы мәнге қайтарады.

Сайт: https://cerulean-platypus-0f0549.netlify.app/

## 1. Мәселе, пайдаланушы, күтілетін нәтиже
- Мәселе: қызметкер сыртқы ЖИ-ге сұраныс жібергенде ЖСН, БСН, IBAN, банк картасы, телефон немесе email сыртқа кетіп қалуы мүмкін; сонымен қатар сұраныс арқылы қорғанысты айналып өтуге (Jailbreak) әрекет жасалуы мүмкін.
- Пайдаланушы: компания қызметкері, ол ЖИ-ді күнделікті жұмысқа қолданады.
- Күтілетін нәтиже: құпия деректер ЖИ-ге бастапқы күйінде жетпейді; шабуыл сұранысы бұғатталады; қызметкер жауапты қалыпты түрде алады.
- Тексеру шарты: токендеудің Precision/Recall және жіктеудің Accuracy/Macro-F1 көрсеткіштері test шаблондарында өлшенеді, test шаблондары train-де болмайды.
- Курс байланысы: 5-апта (киберқауіпсіздік, DLP-шлюз), 6-апта (оқытушымен оқыту: жіктеу, train/test, қателер матрицасы), 7-апта (NLP: TF-IDF).

## 2. Деректер
- Барлық деректер жасанды (synthetic). Оларды `ai_security_gateway_v2.py` ішіндегі `generate_synthetic_dataset()` жасайды (seed = 42).
- ЖСН, БСН, IBAN, карта нөмірлерінің бақылау соммасы дұрыс, бірақ нақты адамға немесе компанияға тиесілі емес. Нақты жеке деректер қолданылмайды және сыртқа жүктелмейді.
- Дереккөзі мен лицензиясы: топтың өз жасанды деректері, сыртқы дерек жоқ.
- `synthetic_prompts_kz.csv`: 150 негізгі жол (SAFE, SENSITIVE_PII, JAILBREAK, әрқайсысы 50, барлығы 75 шаблон) және 3 шекаралық мысал (id 151–153), олар train/test бөлуіне кірмейді.
- Өңдеу қадамдары: шаблонға жасанды мәндер қою, шаблон идентификаторын (`template_id`) және күтілетін құпия түрлерін (`expected_entities`) жазу, шаблондар бойынша train/test бөлу.

## 3. Әдіс және оның негіздемесі
| Міндет | Таңдалған әдіс | Балама (салыстыру) |
|---|---|---|
| Құпия деректі табу | regex + бақылау соммасы: ЖСН/БСН, IBAN (mod 97), карта (Luhn) | тек regex: кез келген 12 цифр токенделеді (кездейсоқ нөмірлерде қате 100%, бақылау соммасымен 3,6%) |
| Сұранысты жіктеу (SAFE / SENSITIVE_PII / JAILBREAK) | TF-IDF (unigram + bigram) + Multinomial Naive Bayes, NumPy-да өзіміз жазғанбыз | кілт сөз ережесі |
| Токен | кездейсоқ токен (`secrets`), бастапқы мән шлюздің жадындағы vault-та | |
| Сыртқы ЖИ | заглушка (нақты API шақырылмайды) | |

Шлюздің шешімі: ML жіктеуші JAILBREAK десе, сұраныс бұғатталады; әйтпесе құпия дерек табылса, токенмен алмастырылып жіберіледі; табылмаса, сол күйінде жіберіледі. Ақылы қызмет те, GPU да қажет емес.

## 6. Нәтижелер (seed = 42, бөлу шаблондар бойынша)
Train: 108 жол / 54 шаблон. Test: 42 жол / 21 шаблон.

| Көрсеткіш | TF-IDF + NB | Кілт сөз ережесі |
|---|---|---|
| Accuracy (бір бөлу) | 0,881 | 0,857 |
| Macro-F1 (бір бөлу) | 0,877 | 0,850 |
| Accuracy, 20 түрлі бөлудің орташасы | 0,906 (мин 0,833, макс 1,000) | 0,805 |

Қателер матрицасы (NB, test): SAFE-тің 10-ы дұрыс, 2-і SENSITIVE_PII, 2-і JAILBREAK деп қате; SENSITIVE_PII 14/14; JAILBREAK 13/14.

Токендеу сапасы (150 жол, түр бойынша): TP = 126, FP = 0, FN = 0, Precision = 1,0, Recall = 1,0. Бұл жасанды деректердегі нәтиже.

Бір бөлудегі айырмашылық аз (0,881 пен 0,857), ал 20 бөлудің орташасында айқын (0,906 пен 0,805), сондықтан бір сандарға емес, екеуіне сүйеніңіз.

Салыстыру: кездейсоқ бөлуде test жолдарының 33/39-нің шаблоны train-де болғандықтан Accuracy 1,0 шығады; бұл асырылған нәтиже, сондықтан негізгі көрсеткіш ретінде алынбайды.

## 7. Тексеру мысалдары
Скрипт 7 мысалды шығарады (енгізу, ML болжамы, табылған деректер, шлюз шешімі, ЖИ-ге кеткен мәтін, қалпына келтірілген жауап):
1. Қауіпсіз сұраныс: тікелей жіберіледі.
2. Жаңа БСН/ЖСН/IBAN/карта/телефон: токенмен жіберіліп, жауапта қалпына келтіріледі.
3. Jailbreak шабуылы: бұғатталады.
4. Қате жағдайы: ақпараттық қауіпсіздік туралы академиялық сұрақ Jailbreak деп бұғатталады (сенімділік 0,71).
5. Штрих-код (991231400512): бақылау соммасынан өтпейді, токенделмейді.
6. Шектеу: бақылау соммасынан кездейсоқ өтетін код қате токенделеді.
7. Шектеу: аты-жөні токенделмейді.

## 8. Шектеулер
1. Модель мазмұнды емес, кілт сөздерді «көреді», сондықтан академиялық қауіпсіздік сұрағы шабуыл болып танылады (мысал 4).
2. Бақылау соммасы қажетті, бірақ жеткіліксіз шарт: кездейсоқ 12 таңбалы нөмірлердің 1000-нан 36-сы (3,6%) БСН/ЖСН болып қате токенделеді (мысал 6).
3. Аты-жөні токенделмейді (мысал 7).
4. Деректер 75 жасанды шаблоннан жасалған, нәтиже нақты корпоративтік мәтіндерге жалпыланады деп айтуға болмайды.
5. Vault тек жадта тұр, өндірістік қолдануда құпия сақтау қоймасы қажет.
6. Сайттағы Jailbreak белгісі ықшам кілт сөз ережесі, нақты NB моделі тек Python кодында.
7. Сыртқы ЖИ-дің орнына заглушка тұр.
